# StockPilot learning evaluation

This directory is a transparent record of implementation progress, engineering quality, and observed learning patterns during the interview-preparation project.

## How this works

- Evaluations are based on inspected code, test output, design explanations, and debugging decisions.
- Scores are provisional and evidence-based. A score is not a judgment of general ability.
- Each review records what was observed, what remains unverified, and the next improvement target.
- Strengths and weaknesses are hypotheses until repeated across multiple tasks.
- No source files are changed as part of an evaluation unless explicitly agreed.

## Scoring rubric (10 points)

| Dimension | What is assessed |
|---|---|
| Correctness | Does the implementation satisfy the stated behavior? |
| Design | Are responsibilities and abstractions placed appropriately? |
| Code quality | Naming, formatting, typing, readability, maintainability |
| Testing | Relevant assertions, edge cases, test isolation, executed results |
| Engineering judgment | Trade-offs, security, failure modes, and ability to explain decisions |

Each task receives a score out of 10, plus a confidence label:
- High: implementation and tests were inspected and executed.
- Medium: implementation inspected; execution unavailable or incomplete.
- Low: limited evidence.

## Progress records

- `scorecard.md`: current scores and aggregate progress.
- `journal.md`: chronological observations and next actions.
- `skills-profile.md`: evidence-backed strengths, development areas, and confidence.
